# 产品盘问记录

## 已确认

| 轮次 | 问题 | 结论 |
| --- | --- | --- |
| 1 | 作品集面向谁 | AI 产品经理岗位 |
| 2 | 首要用户是谁 | 主要为新手个体卖家，次要为依赖人工表格和经验的小团队 |
| 3 | 平台和市场 | TikTok Shop 美国站 |
| 4 | 核心场景 | V1 覆盖完整选品链路，第一优先级是从市场趋势发现潜力品 |
| 5 | 当前流程与痛点 | 看热门内容、查商品、找竞品、查货源与利润、人工决策；查商品和找竞品最耗时 |
| 6 | 潜力品标准 | 需求增长、传播潜力、毛利率、供应稳定性、物流难度、合规风险 |
| 7 | 竞品的作用 | 只提供参考证据，不作为独立评分维度 |
| 8 | 权重与决策边界 | 权重由测评集验证；不一票否决；最终由运营人员选择 |
| 9 | 原计划的测评标签 | 计划由有经验的运营人员评审；暂无真实经营数据 |
| 10 | Demo 数据 | 全部使用模拟数据 |
| 11 | 任务输入 | 类目必填，其他经营约束可选 |
| 12 | 结果与操作 | 接受候选列表、单品详情、多品对比、人工确认和报告输出的 V1 基线，后续按原型成果调整 |
| 13 | AI 职责边界 | 规则系统负责确定性计算与记录，AI 负责分析和解释，用户负责核验与最终决策 |
| 14 | 工作流与执行架构（早期方案） | 曾计划由 Dify 编排、Hermes 执行模拟数据、后端评分并真实写入飞书；该方案已被第 24 轮最终决策替代 |
| 15 | 当前评测证据 | 无法邀请运营专家；先制作明确标注的合成测评方案与模拟结果，不宣称专家验证或真实效果 |
| 16 | Demo 范围 | 接受从任务创建、执行追踪、候选分析、对比与重算，到人工确认和飞书保存的完整交互链路 |
| 17 | 用户研究证据 | 使用虚拟用户、模拟访谈和虚拟业务数据演示功能与验证想法，并明确不代表真实用户验证 |
| 18 | 失败与降级 | 接受数据读取、字段缺失、模型失败、飞书失败、参数异常和重复提交等 Bad Case 及恢复路径 |
| 19 | 版本路线 | 接受从辅助发现到受控执行的演进，但当前只实施和验证 V1，V2 至 V4 仅作规划 |
| 20 | V1 验收标准 | 接受功能链路、失败恢复、证据边界、八章作品集和响应式体验共 15 项完成标准 |
| 21 | 集成准备状态 | Dify 未开通，模型 API 已具备，飞书权限不确定，Hermes Provider 未配置 |
| 22 | Dify 部署与成本 | 接受 Dify Cloud，V1 先使用免费 Sandbox 与已有模型 API，不进行本地自部署 |
| 23 | 公开交付 | Demo 需要公网部署，后续打包发布到 GitHub 作为作品集演示项目 |
| 24 | V1 执行模式 | 取消所有者验证模式；只实现公开交互式 Mock，Dify、Hermes、模型和飞书均不真实调用 |
| 25 | 技术方案与生产映射 | 使用 React、TypeScript、Vite 的纯前端交互式 Mock；作品集必须逐项说明真实生产应用方式 |
| 26 | 页面视觉方向 | 使用 Hallmark Workbench 结构与浅色 Cobalt 主题，第一屏直接进入选品工作台 |

## 最终状态

- V1 使用 Hallmark Workbench 结构与浅色 Cobalt 主题。
- V1 只实现公开交互式 Mock，不真实调用 Dify、Hermes、模型或飞书。
- 真实生产方案保留 Dify 编排、Hermes 受控执行、规则服务计算、运营人员决策和飞书资产沉淀的职责设计。
