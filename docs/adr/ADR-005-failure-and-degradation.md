# ADR-005: V1 失败处理与降级策略

- 状态：已确认
- 日期：2026-07-23

## 背景

Dify、Hermes、模型服务和飞书均可能失败，模拟数据也可能缺失或异常。Demo 需要展示产品如何识别、解释和恢复失败，而不是只演示理想路径。这些失败案例也将作为后续工作的 Bad Case 基线。

## 决策

| 场景 | 系统行为 | 用户选择 | 记录要求 |
| --- | --- | --- | --- |
| Hermes 数据读取失败 | 标记执行节点失败，不生成虚假数据 | 重试或结束任务 | 保存错误类型、时间和重试次数 |
| 输入数据字段缺失 | 降低结果置信度，并标明缺失字段 | 补充数据或继续查看有限结果 | 保存缺失字段及其影响 |
| Dify 或模型调用失败 | 保留已完成的规则评分，AI 解释显示不可用 | 重试分析或仅查看规则结果 | 保存失败节点和已有产物 |
| 飞书保存失败 | 系统内报告保持成功状态，飞书发布单独标记失败 | 重新发布 | 保存目标、错误和幂等键 |
| 评分参数异常 | 阻止本次计算，不返回误导性分数 | 修正参数后重新计算 | 保存校验结果，不记录为有效评分版本 |
| 重复提交 | 复用已有任务或阻止重复写入 | 查看现有结果 | 使用幂等键关联重复请求 |

## 通用原则

1. 失败状态必须可见，不能用默认成功结果掩盖错误。
2. 已完成的确定性计算和用户输入应尽可能保留。
3. AI 不得补齐不存在的事实或把缺失信息描述成确定结论。
4. 外部写入与内部报告状态分开管理。
5. 重试必须有次数限制，并避免产生重复任务或重复飞书文档。
6. 每个 Bad Case 都应包含触发条件、预期行为、实际行为和改进记录。
