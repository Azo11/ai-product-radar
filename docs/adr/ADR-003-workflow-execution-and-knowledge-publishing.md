# ADR-003: Dify 编排、Hermes 执行与飞书资产沉淀

- 状态：已被 ADR-008 替代
- 日期：2026-07-23

## 背景

V1 不仅需要展示 AI 分析结果，还要体现可观察、可评测的工作流编排，以及分析资产的持续沉淀。Dify、Hermes、业务后端和飞书容易出现职责重叠，因此需要明确边界。

> 2026-07-23 更新：V1 已改为公开交互式 Mock Demo。本文保留为目标架构记录，不再代表当前实现和验收范围。

## 原决策（已废止）

以下内容记录方案演进，不属于 V1 当前实现：

1. Dify 作为工作流编排层。
2. Hermes 作为受控执行层，负责读取、采集、清洗和汇总数据。
3. 业务后端负责确定性计算、六维评分、任务状态、权限和持久化。
4. 飞书企业知识库用于保存用户确认后的可读分析资产，不作为唯一业务数据库。
5. Hermes 执行本地模拟数据，不宣称已完成 TikTok 或第三方平台的真实采集。
6. 报告真实写入飞书，并通过回读验证保存结果。
7. 真实平台采集与生产级企业控制能力进入后续规划。

## 原计划工作流（未实施）

1. 产品后端接收类目和可选经营约束。
2. Dify 创建并编排选品分析运行。
3. Dify 调用 Hermes 读取模拟趋势、商品、竞品和供应链数据。
4. 系统检查数据完整性，并调用规则服务计算利润、物流指标和六维加权分数。
5. Dify 调用模型生成趋势总结、传播潜力分析、竞品参考、风险提示和评分解释。
6. 产品展示候选列表与证据，用户调整参数或确认结果。
7. 用户主动触发保存后，系统将报告写入飞书企业知识库，并回读验证。

## 约束

- Dify 不承担业务数据库职责。
- 毛利、费用、物流指标和总分不能依赖模型自由生成。
- Hermes 的工具权限、可访问数据源和输出格式必须受系统约束。
- 外部采集和飞书写入需要授权、审计和失败记录。
- AI 解释必须引用本次运行中的结构化证据。
- 任一外部服务失败时，系统保留任务状态和已有结果，不伪造成功。

## 未来真实集成的验收证据

- Dify 工作流与节点运行记录。
- Hermes 执行日志及输入输出结构。
- 评分服务独立复算结果。
- 飞书写入后的回读验证记录。
- 真实执行链路、模拟市场数据和未来生产能力的明确区分。

以上证据当前均未取得；V1 已实现范围以 ADR-008 和 ADR-009 为准。
