# ADR-007: 公网 Demo 与 GitHub 交付

- 状态：已确认
- 日期：2026-07-23

## 背景

V1 需要公开部署，供面试官随时访问，并在后续打包发布到 GitHub。Dify、模型、Hermes 和飞书均涉及服务端调用、额度或凭据，不能把本地 Demo 的权限模型直接暴露到公网。

## 决策

1. V1 提供可公开访问的 Demo URL。
2. 项目代码、模拟数据、部署说明和必要的工作流资产后续发布到 GitHub。
3. 前端不保存或暴露模型、Dify、Hermes、飞书等服务的密钥和令牌。
4. GitHub 仓库不提交真实凭据、飞书文档标识或内部地址。
5. V1 使用 GitHub Pages 托管构建后的静态站点。

> 2026-07-23 更新：根据 ADR-008，V1 不再进行任何真实外部调用，因此不再建设双模式或飞书写入权限。公网 Demo 只运行交互式 Mock 流程。

## GitHub 交付资产

- 产品与技术文档
- React、TypeScript、Vite 前端源码
- 脱敏后的模拟数据
- GitHub Pages 构建与部署配置
- 测试、验收和 Demo 证据
- Mock 能力与真实集成能力清单

## 未来真实集成要求

- Dify Cloud 只调用受认证的公网后端或 Hermes Adapter，不能直接依赖本机地址。
- 公网服务需要限额、超时、幂等、防重复提交和基础滥用防护。
- 真实飞书写入需要单独设计权限门槛，不能默认向匿名访客开放。
