# ADR-009: 静态交互式 Demo 与真实生产应用映射

- 状态：已确认
- 日期：2026-07-23

## 决策

V1 使用 React、TypeScript 和 Vite 构建纯前端交互式 Mock，部署到静态托管平台。作品集必须将每项 Demo 能力映射到真实生产应用方式，并持续区分“已实现、已模拟、未来需要验证”三种状态。

## V1 技术实现

- React + TypeScript + Vite
- 本地 JSON 保存模拟商品、趋势、竞品、供应链和预生成 AI 内容
- 前端真实执行筛选、排序、六维评分、商品对比和参数重算
- 浏览器本地存储保存任务、收藏、用户判断和报告
- 浏览器使用 jsPDF 将报告内容生成本地 PDF 文件
- 本地 Markdown 与 JSON 保存飞书知识库模拟文档和 Mock 写入载荷
- Mock 展示 Dify、Hermes、模型分析和飞书保存的状态、日志、失败与恢复
- 无后端、无数据库、无真实外部服务调用、无 API 密钥
- 支持静态托管和 GitHub Pages 发布

## 作品集统一对照

| 能力 | V1 Demo | 真实生产应用 |
| --- | --- | --- |
| 市场数据 | 本地合成 JSON | 官方 API、授权数据供应商或合规采集服务 |
| 工作流编排 | 前端 Mock Dify 节点和状态 | Dify Cloud 编排真实节点、变量、分支和运行日志 |
| 工具执行 | 前端 Mock Hermes 日志 | Hermes 在受控权限下调用采集、清洗和内部工具 |
| AI 分析 | 预生成并审核的固定结果 | 模型基于结构化证据生成解释，并记录版本和引用 |
| 六维评分 | 前端规则真实计算 | 服务端规则引擎计算、校验、版本化并持久化 |
| 数据保存 | 浏览器本地存储 | 数据库保存任务、证据、评分、人工判断和审计记录 |
| 报告导出 | 浏览器生成并下载 PDF | 服务端模板化生成、版本化存储并提供受控下载 |
| 飞书沉淀 | Mock 保存状态 | 服务端授权写入企业知识库，并回读验证和幂等控制 |
| 身份权限 | 无登录的公开体验 | SSO、RBAC、租户隔离、配额和审批 |
| 效果评估 | 合成案例与模拟结果 | 真实专家标注、离线评测、用户测试和线上业务指标 |
| 监控运维 | Mock Bad Case | 日志、告警、重试、降级、审计、成本和服务监控 |

## 写作规则

1. 八个作品集章节都要说明当前证据等级。
2. 功能截图必须保留“模拟数据”或“Mock”标识。
3. 目标架构使用“真实生产应用设计”，不能写成“当前系统已实现”。
4. 效果评估分为模拟结果、目标指标和未来验证方案。
5. Demo 展示重点是产品流程、交互、规则和异常设计，不用动画冒充真实外部调用。
