# ADR-008: V1 仅实现公开交互式 Mock Demo

- 状态：已确认
- 日期：2026-07-23
- 替代：ADR-003 中的真实 Dify、Hermes 和飞书集成决策；ADR-007 中的双模式设想

## 背景

V1 的首要目标是稳定、公开地展示产品功能和验证产品想法。真实 Dify、Hermes、模型和飞书集成会引入账号、额度、凭据、网络、延迟和滥用风险，但不是当前 Demo 的必要条件。

## 决策

1. V1 只提供一个公开体验模式，不建设所有者验证模式。
2. 市场、商品、竞品和供应链数据使用本地合成数据。
3. AI 分析和报告内容使用提前生成、审核并版本化的模拟结果。
4. Dify 工作流、Hermes 执行过程和飞书保存均使用 Mock 状态与预设日志演示。
5. 毛利率、费用、六维评分、排序、筛选、对比和参数重算仍由真实业务规则执行。
6. 用户操作、状态变化、失败分支和恢复路径必须真实可交互，不能只播放定时动画。
7. 所有 Mock 节点和模拟数据在界面、文档与 Demo 讲解中清晰标识。
8. Dify、Hermes、模型 API 和飞书真实集成移出 V1，不作为验收项。

## 能力表述

### 可以表述

- 设计了以 Dify 为编排层、Hermes 为执行层、飞书为知识资产库的目标架构。
- 使用交互式 Mock Demo 验证了选品流程、信息结构、规则计算和异常状态设计。
- 为未来真实集成定义了接口、状态、失败与降级边界。

### 不可以表述

- 已使用 Dify 编排真实工作流。
- 已通过 Hermes 采集或总结数据。
- 已调用真实大模型生成分析。
- 已将报告真实保存到飞书知识库。

## 后果

- 公网 Demo 可以无外部凭据运行，部署成本和失败概率显著降低。
- Demo 的技术证明力低于真实集成版本，需要通过清晰架构、交互完整性、规则可复算性和 Bad Case 设计体现产品能力。
- 后续若重新引入真实集成，需要新增 ADR 和独立验收证据，不能直接修改 Mock 标签。
